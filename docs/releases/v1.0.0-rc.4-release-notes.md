## Verify and install

Check the installer's hash and signature before you run it:

```powershell
Get-FileHash 'CivicCast (Native)_1.0.0-rc.4_x64-setup.exe' -Algorithm SHA256
Get-AuthenticodeSignature 'CivicCast (Native)_1.0.0-rc.4_x64-setup.exe' | Format-List Status, SignerCertificate, TimeStamperCertificate
```

You should see the SHA-256 above, `Status` Valid, signer `CN=Scott Converse`, and a Microsoft timestamp. If anything differs, stop. Then follow the [Windows installation guide](https://github.com/scottconverse/civiccast-native/blob/main/INSTALL-WINDOWS.md) and the [release-trust guide](https://github.com/scottconverse/civiccast-native/blob/main/docs/install/windows-release-trust.md).

- Run setup at the station computer itself, not over a remote shell.
- Upgrading from rc.3: back up the station and leave disk headroom. Do not uninstall first; setup upgrades in place and keeps your data.
- If an upgrade fails, setup restores the previous station. Keep the installer log and don't retry blindly.
- Save the recovery kit during First Setup.

## What changed since rc.3

**Programmes and hand-overs**

- Programme hand-overs no longer drop to the filler slate when Windows briefly locks a caption boundary file. The hand-over now retries instead of failing.
- Hardware encoders now produce 2-second video segments. Before this, segments on some machines were longer than the player expected.
- Repeat starts and schedule boundaries are preserved, and as-run accounting handles overlapping airtime correctly. This carries over from the earlier rc.4 kit; that code is unchanged.

**Captions**

- Live captions use a profile measured on CPU-only stations.
- The live caption self-check now checks only what a capture can actually contain. Before, it reported many false failures; it now passes about 93–97% of the time on healthy channels.
- The caption proof now reads the whole live window, so a positive proof reaches the database, API and operator screen.

**AI features**

- The station starts with live translation off when the translation model is unavailable. Before, startup failed.
- The station's readiness check counts only its own AI runtime (Ollama), not another copy on the same port.
- If another program holds the AI port (127.0.0.1:11434), setup now names that program in a warning. The station still installs and starts, with AI features off. To turn AI on, close that program and restart the CivicCast service. Before, setup could hang and roll back.

**Install and uninstall**

- A fresh install no longer inherits an administrator account left behind by an old LocalSystem-era install. Upgrades still migrate the account as before.
- Uninstall removes the old LocalSystem profile copy once it has been migrated.
- A silent uninstall never hangs.
- Service folder permissions are granted correctly even while another process is using the folder.

**Security**

- Bundled Expat, OpenSSL (psycopg), GLib, libsoup and GStreamer FFmpeg libraries were updated.
- Security scanning now also covers native libraries inside shipped Python wheels.

## Known issues

- **Ryzen 9 black pictures (historical):**
  - Not reproduced on this candidate, including on the Ryzen 9 machine where it was first seen (0 black samples).
  - Cause unknown.
- **Captions are machine-generated:**
  - Delay is measured, but accuracy is not calibrated against human transcripts.
  - At a programme change, a caption page still being spoken can be cut off. This is intentional, so old text never carries into the next programme.
- **Uninstall leftovers:**
  - `C:\Program Files\CivicCast (Native)\uninstall.exe`
  - The Windows service-account profile folder `C:\Windows\ServiceProfiles\CivicCastSupervisor`. Windows holds this folder open, and it contains one Windows credential-store file.
- **Gate A sandbox:**
  - The automated Windows Sandbox acceptance run freezes inside the sandbox, so it does not give a verdict on this candidate.
  - This is a problem with the test harness, not the product: the station installed, came up healthy and passed its caption job before the freeze.
  - Clean-install and upgrade acceptance were run on real machines instead (see above).
- **Bundled AI runtime advisory:**
  - A scan of the installed payload flags GO-2026-6860 (High): slow parsing of crafted HTML in the Go `golang.org/x/net` 0.61.0 library built into the bundled `ollama.exe`. The advisory was published October 27, 2026.
  - CivicCast's Ollama listens only on 127.0.0.1 and receives input only from the station, so the exposure is limited to the station itself.
  - It will be fixed when an Ollama build with x/net 0.62.0 is bundled.
- **Platform:**
  - Windows 11 is the verified platform; Windows 10 and Windows Server are not verified.
  - No minimum hardware specification is certified for three channels.
