## The minimum machine is 32 GB of RAM

The smallest machine CivicCast supports is **32 GB of RAM**, as in rc.8. A processor with integrated graphics is enough; **no separate graphics card is required**. A 16 GB machine is below this minimum.

## What was checked

The owner ordered this release without the publisher's physical-host consumer receipt and without a Gate A station-acceptance run. Four development stations with 32 GB or more (two NVIDIA, two AMD integrated graphics) were upgraded to exactly this signed build. All three channels on each station were checked for cable output, captions and real video. This was a short check, not a long soak.

## What changed


Release candidate **v1.0.0-rc.9**. It replaces v1.0.0-rc.8.

- Every TS mux now guards against a future-dated closing frame, so the cable output no longer crashes on it (#400).
- Automatic H.264 encoding prefers the Media Foundation encoder over nvh264enc (#402).
- The stall watchdog now sees a cable mux that has audio but no video (#401).
- The native vulnerability audit is clean against the 2026-11-28 scanner database. Five FFmpeg advisories (CVE-2026-135705, -135713, -135714, -135715, -135721) and seven new ones (CVE-2026-137905 .. -137911) were added to the database after the previous pass; all twelve are recorded per ID in `security/native-audit-triage.json` — the standalone FFmpeg pin `N-129333-g7fdb4c2341` already contains every upstream fix commit, and the component touched is not compiled into the minimal PyAV or GStreamer FFmpeg builds.
- The standalone FFmpeg runtime is repinned from `N-128227-g4811625b5f` (2026-10-31 monthly) to `N-129333-g7fdb4c2341` (2026-11-27 autobuild, 83,011,078 bytes, sha256 `b05c6b78...`), the newest BtbN build past the 9.1 tag. Thirteen of the 2026-11-24 FFmpeg advisories (CVE-2026-135733 .. -135745, including two Criticals in `deband` and `dynaudnorm`, plus the zmq loopback default) were fixed upstream only on 2026-11-17/19, after the old pin; all 37 newly published IDs have their upstream fix commit in the new snapshot (per-ID proof in `security/native-audit-triage.json`). Same nine-file PE closure, LGPL v3 self-report, `--disable-libx264 --disable-libx265`, real h264/aac encode proof passed. The embedded PyAV and GStreamer FFmpeg builds are unchanged and triaged per ID.
- An operator can put a station logo on air (issue #348). Before: the station bug could draw a logo but nothing connected an operator's image to it, and a CG board's logo zone had no way to name an image, so a station had no way to show its own logo. Now: the **Lower-third banner** box on **Channels** has a **Station logo** part -- upload a PNG or JPEG up to 2 MB, see a small preview, remove it, and tick **Show logo on air**. The station stores one logo per channel and refuses SVG, GIF, damaged, oversized (over 2 MB) and too-large (over 1920 x 1080) images with a plain reason. In **CG Designer**, a zone whose content source is **Image** can choose **Station logo**. Both follow the overlay's existing rule: the change lands on the channel's next pipeline build. A missing or damaged logo falls back to no logo, with one warning, and the channel stays on air.

## Known issues

- OpenSSL 3.5.9 advisories (November 17, 2026) are still open, as in rc.8; the per-ID review is in `security/native-audit-triage.json`.
- No real cable headend has received this feed; cable checks are software probes.
- No Intel integrated-graphics station was tested.
- No six-hour run was made on this exact build. The fixes in it (#400, #401, #402) had six-hour runs on development stations on November 27, 2026, before this build.
- Captions on cable (#342), a lost reload holding a channel on the slate (#344), and health during a worker restart loop (#327) were listed in rc.7 and rc.8. None was re-tested on this build.
- YouTube Live from the Publish page was not tested on this build.
- The installer does not block a machine with less than 32 GB of RAM. 32 GB is the stated minimum.
- The user manual in this release was built before publish. It describes the rc.9 edition but says the published release is v1.0.0-rc.8, and two places still name the rc.8 edition. These release notes are the current record.

## Install / upgrade

Use the release-matched `scripts/download_windows_release_artifacts.ps1` with `-Tag` and `-Version` set to this release and `-Install`. It downloads and verifies the signed `setup.exe`, runtime packs, multipart station-model bundle, checksums and sidecar, then runs setup with `/S`. Do not install from `setup.exe` alone. Package availability does not establish fresh-install, repair, upgrade-preservation or sustained-operation acceptance; follow the current owner-authorized handoff and INSTALL-WINDOWS.md.

## SmartScreen note

Before responding to any blue "Windows protected your PC" SmartScreen warning, verify the exact SHA-256 and that Get-AuthenticodeSignature reports Status Valid for publisher Scott Converse. A warning alone proves neither signature failure nor a valid publisher; if the expected More info or Run anyway options are missing, or the publisher/hash differs, stop. SmartScreen reputation is separate from Authenticode validity and may vary.
