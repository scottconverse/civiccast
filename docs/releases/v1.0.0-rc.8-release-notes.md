## The minimum machine is now 32 GB of RAM

The smallest machine CivicCast supports is now **32 GB of RAM**. A processor with integrated graphics is enough; **no separate graphics card is required**. A separate NVIDIA card is still useful — it can speed up Whisper backup captions and allow the larger summary model — but it is not a requirement. Integrated AMD graphics are covered by the soak below; Intel integrated graphics were not tested on this build, so they are allowed by the requirement but unproven in the field.

A 16 GB machine is **below this minimum and is not a supported configuration**. One was run during this build's soak (the MSI, captions off): it stayed on air, but with high CPU and low memory. Do not plan a new station at 16 GB.

The model tiers have their own memory numbers (for example, the 12B summary model needs 16 GB). Those are requirements of that model, not of the station as a whole.

## What changed since rc.7

**A programme change stays on air on a busy or hybrid station (#379)**

Before: a preparation step that overran its window could leave a channel dark, and preparing a long programme could fall behind its own speed estimate. Now: preparation is held inside its processor budget, its warm-up uses the real measured speed, the sooner warm is kept first, and a reload that overruns no longer strands the channel on its slate. This was measured on a hybrid test box; a 16 GB box is still below the supported minimum and this fix does not make it a supported machine.

**The cable output no longer takes the public channel off the air (#378)**

Before: on Blackwell-class NVIDIA cards, the cable `udp-ts` output branch could pull the public output off the air. Now: that branch no longer does.

**Audio timestamps never step back on an immediate finite reload (#381)**

Before: an immediate finite source reload could step the audio timestamps backwards. Now: the egress audio presentation timestamps never move back.

**A deferred rollover is driven from the end of stream (#380, #382)**

Before: a deferred rollover's lead was sized from a guessed speed, the warm queue could starve long programmes, and the watchdog timing was loose. Now: the rollover lead is sized from the plan the dispatch will actually prepare and from a real speed, the rollover is driven from the end of stream, and the watchdog is delayed only as needed.

**Live captions run the speech child on the performance cores**

The Whistle speech child now runs on the performance cores of a hybrid processor, so on-air recognition keeps its share of the CPU when background work would otherwise contend for it.

**Install grants the installer account the Postgres bin rights it needs (#377)**

Before: setup could fail with "Access is denied" on a Dell because the installing account could not read the Postgres bin. Now: the native install grants that account read-and-execute on the Postgres bin before it runs `pg_ctl`.

### Soak: five stations, all three channels

Read at 1:26 PM MST on November 23, 2026. All three channels played real video on every station. The stations were still running at that reading.

| Station | Graphics | RAM installed (Windows shows) | Install type | Captions | On air in one stretch (h) |
| --- | --- | --- | --- | --- | --- |
| 5070 Ti | NVIDIA RTX 5070 Ti | 32 GB (31.6) | upgrade | on | 38.6 |
| R9 | AMD 780M (integrated) | 32 GB (25.8) | clean | on | 37.2 to 37.4 |
| 5060 Ti | NVIDIA RTX 5060 Ti | 32 GB (31.3) | clean | on | 36.6 to 36.7 |
| MSI | Intel UHD + NVIDIA RTX 4050 laptop GPU | 16 GB (15.7) | clean | off | 36.0 to 36.2 |
| Beelink | AMD 780M (integrated) | 64 GB (47.8) | upgrade | on | 21.6 to 21.7 |

Four stations were on air for 36 hours or more in one stretch. The Beelink was restarted by hand at 3:43 PM on November 22, so its figure counts from then.

- **Restarts:** the 5060 Ti, R9 and Beelink had playout-worker restarts and a few slate minutes in the first hours after install. The logs show these came from station set-up (channels started before their schedule was loaded) and, on the Beelink, a manual restart. The 5070 Ti, 5060 Ti and R9 logged none after about 1 AM on November 22. The 5070 Ti logged one start restart and no slate minute at all. The MSI shows a short slate card (about 10 to 60 seconds) at some program changes, about one or two an hour, because the next program is not always ready in time on a 16 GB machine. The full per-station counts are in the verification record.
- **Two of the five (Beelink and R9) run on AMD integrated graphics with no separate card**, which is what the new minimum allows. The Beelink has 64 GB installed and the R9 has 32 GB installed (read from their memory modules; Windows shows less because the integrated graphics reserve part of it), so both meet the 32 GB minimum.
- **The MSI is a 16 GB machine (Intel UHD plus an NVIDIA RTX 4050 laptop GPU, captions off), below the minimum.** It stayed on air for the whole run with high CPU (peak 93%) and very low free memory (down to 1.5 GB) and is not proof that a 16 GB machine is supported. A second 16 GB machine, a laptop with a GTX 1660 Ti, ran for a 30-minute check with 0 slate minutes after a slow start (40 to 60 minutes before real video). It is not proof either.
- This is **not** a 48-hour soak. No Intel integrated-graphics station was tested. The logger does not count watchdog firings.

## One open item

**OpenSSL 3.5.9 has security advisories dated November 17, 2026.** The fix version, 3.5.10, had no downloadable release when this build was checked on November 22, 2026.

Review result (2026-11-22, against the exact files in this kit): **29 advisory findings** across the OpenSSL copies that ship in the kit. **28 are not reachable** from the shipped programs, plugins and CivicCast code. **1 is not proven:** `gstreamer-openssl 3.5.9` + `CVE-2026-95690`. `gioopenssl.dll` contains the DTLS entry points; no shipped program, plugin, or CivicCast code was found that calls them; shipped PyGObject could construct a DTLS connection; this was NOT proven at run time; the owner accepted this for rc.8 on 2026-11-22; replace with OpenSSL 3.5.10 when it is released.

The evidence is static file evidence only — import tables, string tables and source read from the shipped files. Nothing in the kit was run. The fix ships in a later build when OpenSSL 3.5.10 exists.

## Known issues

- This is a beta release candidate (rc.8). It is published and supersedes rc.7.
- No 48-hour soak exists for this build (four stations ran 36 to 39 hours, one about 22). No Intel integrated-graphics station was tested.
- The 16 GB MSI stayed on air only with captions **off** and with high CPU and low memory. It is below the minimum and is not a supported configuration.
- OpenSSL 3.5.9 advisories remain open; see the open item above. Of the 29 findings, 28 were reviewed as not reachable on these exact files and 1 (`gstreamer-openssl 3.5.9` + `CVE-2026-95690`) is not proven.
- **The kit's built-in manual is out of date on the minimum machine.** The manual shipped in this kit (`QUICKSTART-OPERATOR.md` and `USER-MANUAL.pdf`/`.docx`) still says that no minimum hardware specification is certified. The 32 GB minimum stated in these notes is the rule. The installer shows the machine's memory but does not block an install on a machine under 32 GB.
- **Captions on cable (#342):** small, intermittent caption-writer faults were listed as under investigation in rc.7. Not confirmed fixed or still open on this build.
- **A lost reload can hold a channel on the slate** for up to the watchdog fallback (#344). rc.8 changes reload and rollover handling, but this item was not re-tested on this build, so it is neither confirmed fixed nor confirmed open.
- **Health during a worker restart loop (#327):** a playout worker that restarts repeatedly can still be reported as healthy. Not re-tested on this build.
- **YouTube Live from the Publish page** (the Google sign-in path) was not tested on this build.
- **No real cable headend has received this feed.** Cable checks are software probes, not a headend.
